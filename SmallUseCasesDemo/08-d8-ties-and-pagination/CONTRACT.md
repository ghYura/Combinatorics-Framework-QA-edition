# D8a contract v1 — weak orders and stable pagination

Status: frozen before implementation. Apply ../README.md, gates G1–G7.
Question: which deterministic pagination policies violate a declared stable-order
contract when identified records tie? Population: every weak order of four fixed
records, both directions, three policies. Each case has equal weight and one
attempt (K=1); no reduction or sampling. Counts describe this finite fixture,
not production failure probabilities. No mutable server or actual HTTP is needed.

## Frozen population and API

Records A,B,C,D have immutable input positions i=0,1,2,3. Their rank vector has
four integers in 0..3 and uses exactly {0,...,max(rank)}. Enumerating these vectors
gives 75 ordered partitions: sum(k! S(4,k)) = 1+14+36+24. This is not the 15
unordered set partitions or restricted-growth strings. Identity survives ties;
rank relabelling is already canonical, and record permutations are not quotiented.
Directions are asc and desc. Page size is 2; dataset and original input order
remain fixed across all requests. Let s=+1 for asc, -1 for desc.

Stable output orders records by (s*rank_i, i): within ties, original input order
is preserved for BOTH directions. Three policies implement these exact rules:

| Policy | Comparator key | Pagination |
|---|---|---|
| stable_cursor | (s*rank_i, i) | Strict key > incoming composite cursor; first two eligible records. |
| score_only_cursor | (s*rank_i,) | Strict key > incoming primary-only cursor; first two eligible records. |
| alternating_ties | (s*rank_i, i) on even requests, (s*rank_i, -i) on odd requests | Fresh sort per request, offset=2*request, take two. |

Requests are indexed 0,1,2. Cursor policies start with null; nonempty pages set
the outgoing cursor to the last returned key. Empty pages have outgoing null.
Offset policy has null incoming/outgoing cursors. Cursor policies have null offset.
Sort the full input A,B,C,D on every request using the actual comparator;
score_only_cursor's equal-key sort preserves that input order. Use cmp_to_key
or an equivalent route that makes the comparator under test drive the sort.
Stop at the first empty page, recording it; allow at most three requests. Runtime
owns this bound and loop. All frozen cases terminate within it. No hidden fourth
request, retry, deduplication, repair, or fallback is allowed.

Identity: `policy|D=asc_or_desc|R=four_rank_digits`.
Preregistered observations are in architect-derived.json, generated by derive.py.
Raw Core support after DISTINCT = 75*3*2 = 450; no sieve, optional multiplier 1;
post-Core/Reader/rendered/Executor unique cases and original attempts are all 450.
Derived outcomes: stable_cursor 150 PASS/0 DOMAIN_FAIL; score_only_cursor 108/42;
alternating_ties 72/78; total **330/120**. Per direction these are 75/0, 54/21,
36/39. All 24 strict orders per direction pass under every policy.
